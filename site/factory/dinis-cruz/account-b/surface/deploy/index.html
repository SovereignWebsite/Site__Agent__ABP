ABP: the solutions and how to deploy them

Deploying an Agent Behaviour Policy

Not every gap can be closed from inside Claude, and an ABP is still far better than none. Before it, every line was held by the text of the instructions alone; after it, on this site's repository, 19 of 35 reaches are blocked, 8 logged and 8 granted by name. Two layers, and you need both:

1. The hard boundaries first (outside Claude)

  1. A separate agent account for agents, with only the connectors the work needs. It is the only thing that removes the top half of the default map: a hook guards only sessions on its own repository.
  2. GitHub: branch protection on main, a signed-commit check in CI (this site has one: .github/ci/signers.mjs), and each agent with push only to its own repository.
  3. The environment: take the census and remove network hosts and injected credentials the work does not need.

2. Install the hooks (inside Claude)

From the root of the agent's repository. These are this site's files: the ABP starter kit (0.2.0) with the changes listed below.

mkdir -p .claude/hooks abp
for f in .claude/settings.json .claude/hooks/abp.mjs abp/tools.mjs abp/run-report.schema.json abp/policies.json; do
  curl -sf -o "$f" "https://raw.githubusercontent.com/SovereignWebsite/Site__Agent__ABP/dev/$f"
done
sha256sum .claude/hooks/abp.mjs     # compare with the file on GitHub before you trust it
  1. Edit abp/policies.json: set operator, git.remote_url, identity.label_suffix, and one entry in roles per agent with the paths it writes and the tools it may use. Delete the two roles of this site.
  2. Identity: the hook knows an agent by ABP_ROLE, or by the one key label <role><suffix> in its key store (here b-abp-sovereignwebsite in ~/.sg-send/keys).
  3. Build each agent's ABP: node abp/tools.mjs build, and commit everything.
  4. Start log-only: "mode": "observe" with no breaker on. The hooks take effect at once, even mid-session.
  5. Check it fires: ~/.abp/log/<session>.jsonl shows each call with the agent's name and a decision, the prompt as length and hash only.
  6. Breakers, one rule at a time, in this order: R3 (connectors), R6 with "kinds": ["tamper"] (the hooks and policy themselves), R8 (key reads), R5 (pushes). Test each in a copy first: ABP_POLICY=/tmp/new.json; a broken policy blocks the agent's own writes.
  7. Run reports: node abp/tools.mjs run-report --line "..." before the last commit of each run; the ABP agent reviews them.
