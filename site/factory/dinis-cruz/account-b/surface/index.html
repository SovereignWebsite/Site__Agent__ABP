ABP, account B: a census from the inside

What one agent session can reach

The short version: this session was started with one rule, "You never use a connector". Its own tool list says it can send email as the account's owner, start and read every other session on the account, schedule work that runs after everyone has gone, and call several APIs already signed in. No hook is running to stop it. Only its instructions do.

It changes while you watch

At the start of this session the three connectors were listed under opaque ids, with tool names such as send_message and account-upgrade. A couple of minutes later the same tools reappeared under readable names (Gmail, Suno, Claude Docs). Nothing in the session asked for that. What an agent can reach is not fixed: platforms add features, and anyone with the account can add a connector. So the census is taken again at every start and compared with the last one. The difference is the finding.

Map your own

Paste the census prompt into any agent: Claude, ChatGPT, Mistral, Gemini. It asks the agent to list what it can reach without using any of it, draw the ASCII map, show its instructions against its reach, and then ask you, one family at a time: do you want this session to have this?

What helps, in order

  1. A separate account for agents, with no connectors. It is the only hard boundary against the top half of the map.
  2. Repository permissions, branch protection and a signed-commit check on everything agents push to.
  3. A policy and hooks (the ABP starter kit): a guardrail and an audit log that keep an honest agent on its grant and record every attempt. Not a security boundary.
  4. A census at every start, compared with the last one.
