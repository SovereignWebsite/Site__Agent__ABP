## Round 2, after b.security's post-check (25 Nov, about 20:45 UTC)

b.security passed round 1 as a draft guardrail and named three points. The pattern now reads (replacing the one above):

```json
[
 [
  "R8",
  "(^|\\s)(cat|less|more|head|tail|cp|scp|base64|xxd|od|strings|grep|sed|awk|python3?|node|openssl|ssh-keygen|dd|tar|zip|gpg)\\s[^;|&]*(~|\\$HOME|\\$\\{HOME\\}|/root|/home/[^/\\s]+)/\\.(sw-secret|sg-send|ssh)(/|\\s|$)",
  "never read a key store or private key from the shell"
 ],
 [
  "R8",
  "<\\s*(~|\\$HOME|\\$\\{HOME\\}|/root|/home/[^/\\s]+)/\\.(sw-secret|sg-send|ssh)/",
  "never redirect a key store file into a command"
 ]
]
```

| Call | Result |
|---|---|
| openssl pkey -in ~/.sg-send/keys/.../signing_private.pem | blocked, R8 |
| ssh-keygen -y -f ~/.sw-secret/signing | blocked, R8 |
| dd if=/root/.sw-secret/signing | blocked, R8 |
| sgit pki sign x < ~/.sw-secret/pass (input redirect) | blocked, R8 |
| cat ~/.sw-secret/pass \| sgit pki sign file (the documented signing line) | blocked, R8 |
| tar cf - ${HOME}/.ssh | blocked, R8 |
| bash tools/setup-signing.sh, bash tools/sign.sh | passes |
| git commit -S, ls ~/.sw-secret, cat README.md | passes |

**Signing.** The documented line that pipes the passphrase into `sgit pki sign` would break in enforce mode. The way through: every agent signs with one named script, `tools/sign.sh` (proposed; it does not exist yet, and tools/ is not b.abp's to write), which reads the passphrase inside itself. The hook sees only `bash tools/sign.sh <file>`, so it passes; a direct read is denied.

**b.security's condition on round 2 (20:43 UTC):** since the hook trusts any command line that runs the signing script, both scripts are protected paths. Added to `common.protected`: `tools/sign.sh` and `tools/setup-signing.sh`, owner abp. Tested: Write, Edit, `>>` and `sed -i` on either by another agent block (R6); `bash tools/sign.sh` still passes. Even the abp role cannot write them unless its grant also lists them, so as written only Dinis changes them (by a reviewed commit).

**Still open** (b.security keeps both open until then): the lines are in b.abp's draft only. They land when they are in the kit's template and in a running hook (fix 4).

**Limits:** still a guardrail. A script file, a variable holding the path, or a tool not in the list gets past it. The hard boundary for the key is that it ends with its session and is never committed.
