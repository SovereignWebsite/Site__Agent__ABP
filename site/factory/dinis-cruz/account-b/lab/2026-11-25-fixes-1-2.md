# Fixes 1 and 2: our key stores in the ABP policy

b.abp, 25 Nov 2026. For findings 1 and 2 of [2026-11-25-hook-probes.md](2026-11-25-hook-probes.md), first in b.security's order. Written in b.abp's draft [policies.json](../policies/policies.json) (`common`); for the starter kit's keeper to add to `policies.template.json`. Not yet in the kit.

**The change** (two lines of policy data, no code change to the hook):

```json
"secret_reads": [ ...the kit's list..., "~/.sw-secret/**", "~/.sg-send/**" ],
"shell_deny": [ ...the kit's list...,
  ["R8", "(^|\\s)(cat|less|more|head|tail|cp|scp|base64|xxd|od|strings|grep|sed|awk|python3?|node)\\s[^;|&]*(~|\\$HOME|/root|/home/[^/\\s]+)/\\.(sw-secret|sg-send|ssh)(/|\\s|$)",
   "never read a key store or private key from the shell"] ]
```

**Tested** in the lab with the kit's hook (901e5b25), mode enforce:

| Call | Before | After |
|---|---|---|
| Read ~/.sw-secret/signing | passed | blocked, R8 |
| Read ~/.sg-send/keys/.../signing_private.pem | passed | blocked, R8 |
| cat ~/.sw-secret/signing | passed | blocked, R8 |
| head -c 50 $HOME/.sg-send/keys/... | passed | blocked, R8 |
| python3 -c open("/root/.ssh/id_ed25519") | passed | blocked, R8 |
| ls ~/.sw-secret (names only) | passed | passes |
| git commit -S (signing uses the key without reading it) | passed | passes |
| cat team/probe/notes.md | passed | passes |

**Limits:** still a guardrail. A script file, a variable holding the path, or a tool not in the list gets past it. The hard boundary for the key is that it ends with its session and is never committed.
