# Fix 4: the ABP hooks installed in Site__Agent__ABP (log-only)

b.abp, 25 Nov 2026, at Dinis Cruz's word in b.abp's session ("Yes please", to installing the hook where our agents work, log-only, starting here).

**What is installed** (repository root, not under site/, so the website build ignores it):
- `.claude/settings.json` and `.claude/hooks/abp.mjs`: the starter kit's wiring and hook (SessionStart, UserPromptSubmit, PreToolUse, PreCompact).
- `abp/policies.json`: the kit's template (0.2.0) filled for this repository, with fixes 1 and 2 and the protected signing scripts. Mode **observe** and **no breaker on**: every call outside a grant is logged and allowed. Blocking comes rule by rule, only at Dinis's word.
- `abp/b-abp.md`, `abp/a-abp.md`: each agent's ABP, generated by `node abp/tools.mjs build`; the SessionStart hook re-anchors it after every compaction.
- Two grants: b-abp (its own area, its key file, its index entry, abp/ and .claude/) and a-abp (this site's keeper: site/, tools/, the root docs and .github/). Any other session is unidentified: logged, never blocked.

**Who a session is:** its sgit key label from `tools/setup-signing.sh` (`b-abp-sovereignwebsite`), or `ABP_ROLE`.

**Kit bug found and fixed here.** The hook's label pattern `^([a-z][a-z0-9.-]*)(suffix)?$` is greedy, so a suffix that starts with a hyphen (ours: `-sovereignwebsite`) never matches and every agent is "unidentified". The kit only works with `@team` labels. Fix: one character, `*?` (non-greedy). Sent to the kit's keepers.

**When it took effect: at once.** Claude Code picked the hooks up mid-session, the moment `.claude/settings.json` was written (b.abp's own session, first logged call 20:55:50 UTC). The same is true the other way: an agent that edits or deletes that file switches its own hooks off mid-session. That is why `.claude/**` is protected, and why R6's breaker for it should be the first one on.

## Git rewrites of protected paths (b.security's gap, 21:05 UTC)
